# Meridian

A personal productivity web app for tracking the day's hours, habits, tasks, projects, and the time you spend in each area of your life.

## Running it

```bash
npm install
npm run dev        # http://localhost:5178
npm run build      # type-check + production build into dist/
npm test           # sync-engine tests + database security tests
npm run dev:cloud  # local stand-in for Supabase at http://localhost:54321 (see DEPLOY.md)
```

Everything works offline on one device, stored in the browser (localStorage and IndexedDB). Use **Settings → Export backup** to save a JSON copy, and **Import** to restore one. **Settings → Load sample data** fills the app with a few weeks of realistic data to explore.

To use Meridian on your phone and share projects with friends, put it online with a free Supabase project and static hosting: **see [DEPLOY.md](DEPLOY.md)**.

Once it's on a real address, **Settings → Install Meridian** installs it as an app: its own window, an icon you can pin to the Windows taskbar, the macOS Dock or a phone home screen, and no address bar.

## Features

| View | What it does |
|---|---|
| **Today** | 24-hour clock (outer ring = planned blocks + timed habits, inner ring = time actually logged), agenda, due habits with step checklists, tasks active that day, timer, and logged time by area. Drag around a ring to block out or log time. **Drag a task onto the clock** (from the plan tray under it or the Tasks card; mouse or touch) to plan time for it on the day shown, today or any future day; drag a planned block to move it or its ends to resize it. |
| **Tasks** | Every task, filterable by status/project/area and grouped by priority, project, or date. Tasks have subtasks, a date span (one or many days), priority, prerequisites, any number of **timeframes** (planned work sessions, edited in the task dialog; rows show the next one), and **tags** (typed in the task dialog with suggestions, or `#tag` in quick add). Search matches tags. |
| **Habits** | Weekday schedule, time of day, duration, and ordered steps. Shows strength, streaks, a strength-over-time chart, and a clickable history grid for backfilling. |
| **Calendar** | Month grid with multi-day task bars. Drag across days to create a task; drag a bar or an unscheduled task onto a day to (re)schedule it. |
| **Journal** | A distraction-free page per day that autosaves as you type, with mood, a rotating prompt on blank days, `#tags`, and a time-divider button. The sidebar has a month calendar (dots colored by mood), "your day" (habits, finished tasks, time by area), a 90-day mood chart, searchable past entries, and per-journal settings. Keep several journals (Daily, Gratitude, Dreams…). Tags that belong to a goal link to it, and "Tag a goal…" inserts one. Optional passphrase encryption. |
| **Projects** | Cards with progress and "next up"; a detail page with tasks grouped by priority and filterable by tag, plus a **flow map** where tasks unlock each other (cards show their tags). |
| **Goals** (Projects → Goals) | Open-ended aims that don't fit a task list ("Speak up more in groups", "Build deeper friendships"). Each has a why and a picture of success, a status (exploring / active / paused / achieved / let go) and a rough horizon instead of a deadline. Progress comes from check-ins (1–10 rating, the goal's own reflection prompts, a "next small step"), journal entries carrying the goal's `#tag`, unordered milestones, optional signals (numbers with a trend and target), a small-wins log, and linked habits (practices) and projects. A **weekly review** walks through every open goal; Today shows next steps and when the review is due. |
| **Life areas** | Hours per area per day (stacked columns + table), weekly targets, top activities, and area management (name, color, target). |
| **Health** | Stat tiles with trends for every measurement, time spent in the Health area, health habits, goals, and injuries. You can add custom measurements (waist, 5K time, 1RM…). Goals show a trend line, an estimated arrival date with an 80% range, and the rate needed to hit a deadline. Injuries track pain/mobility check-ins, expected recovery, a projected pain-free date, and linked rehab habits. Fitbit data syncs through the Google Health API. |
| **Account & sharing** (Settings, project **Share**) | Email and password accounts. Every device keeps a full local copy and syncs changes both ways, with live updates and offline catch-up. Share a project by email or invite link as editor or viewer; members see only that project's tasks, task map and notes, and can be assigned tasks, which then show on their Today and Calendar. Installable on Windows, macOS, phones and tablets, and works offline. |
| **Finance** | Separate ledgers (personal + any number of businesses) with accounts, categories, and payees/payers, so every transaction shows *from → to*. Bank CSV import has column mapping, duplicate detection, and auto-categorizing rules. An overview covers income vs. spending, where money went, balances, and who paid whom. A **Taxes** page gives quarterly estimated payments (federal + state), safe-harbor amounts, a set-aside rate, and a Schedule C–style summary per business. |

## Design notes

- **Stack:** React 19 + TypeScript + Vite, Zustand (with `persist`) for state, `@xyflow/react` for the flow map. The charts and clock are hand-written SVG. There is no router library: `lib/hooks.ts#useRoute` reads the URL hash (`#/projects/<id>/flow`).
- **Dates** are local `YYYY-MM-DD` strings (`DateKey`) and times of day are minutes from midnight. Never store UTC timestamps for calendar concepts. `lib/dates.ts` has the helpers.
- **Planned vs logged.** `TimeBlock`s (optionally repeating on weekdays) and timed habits are the *plan*. `TimeEntry`s are what actually happened: from the timer, from checking off a habit (if `logTime`), from "Log as spent" on a block, or entered by hand. Area statistics use entries only.
- **Habit strength** (`lib/habits.ts`): after each scheduled occurrence, `s = s·m + done·(1−m)` with `m = 0.5^(1/13)`. Thirteen completions in a row reach 50%, and 66 reach about 97%. A pending "today" is never counted as a miss.
- **Locks & flow map** (`lib/tasks.ts`): `task.dependsOn` lists prerequisites. A task is *locked* until every prerequisite is done, and locked checkboxes are disabled. Links that would create a cycle are rejected (`wouldCycle`). Completing a task shows an "Unlocked: …" toast. Flow-map positions are saved per task in `task.flow`.
- **Area colors** use slots 1–8 of a palette whose order was validated for color-blind separation. Areas store a `slot`, and CSS variables `--series-N` / `--on-series-N` resolve it for light and dark themes.
- **Sounds** (`lib/sound.ts`) are synthesized with the Web Audio API, so there are no audio files: short sine/triangle notes on a C-major pentatonic scale, low-passed, with a faint echo on chimes. `installUiSounds` adds a soft tap to every button through one document click listener; it waits 30 ms so a specific cue from the handler or its effects (`sound('check')`, dialog `open`, toast `notify`, task `unlock`, timer `start`/`stop`, flow-map `connect`, journal `lock`/`unlock`, `error`, `complete`) replaces it. Opt an element out with `data-sound="off"`. Sounds are skipped while the tab is hidden. On/off and volume are per device (`meridian:sound` in localStorage, not in backups), under Settings → Sounds.
- **Timeframes** (`lib/timeframes.ts`) are ordinary `TimeBlock`s with a `taskId`, so they sync, repeat and log like any block. On the clock they show the task's current title and area (`planForDate` with tasks and projects). Dropping a task (`lib/taskDrag.ts`: pointer events, not HTML5 drag and drop, so touch works; drop targets register with `useTaskDropTarget`) adds a 60-minute block snapped to 15 minutes. The task dialog edits a task's timeframes as a draft and saves them with the task. Deleting a task deletes its one-off timeframes and unlinks repeating ones. The Today Tasks card also lists tasks with a timeframe that day.
- **Tags** (`lib/tags.ts`) are free-form strings on `Task.tags`, matched case-insensitively (the first spelling wins), colored by a stable hash into the categorical palette with the label always shown. They sync with the task, so project members share them. Quick add turns `#word` into a tag only when it starts with a letter, so `#42` stays in the title.
- **Editors** are modal dialogs opened through the small UI store (`ui.ts`): `useUI.getState().open({ kind: 'task', id })`. They edit a local draft and commit on Save.
- **Persisted stores:** `meridian:data` (planner), `meridian:health` and `meridian:finance` in localStorage. `meridian:notes`, `meridian:journal` and `meridian:goals` are in IndexedDB through `lib/idb.ts#idbStateStorage`, which debounces writes and flushes when the tab is hidden. `useHydrated(store)` gates views until the async stores have loaded. `lib/backup.ts` exports, imports, loads samples, and erases all of them together.

### Project notes (Projects → a project → Notes)

- **Storage:** notes live in IndexedDB (`notes/store.ts`, persisted through a debounced zustand storage adapter that flushes on tab hide). Images live in a separate IndexedDB store (`notes/assets.ts`) as Blobs and are referenced as `asset:<id>`. localStorage's ~5 MB cap would fill quickly with pages and images. Photos over 1.5 MB are downscaled to 2000 px; small images such as pixel art are stored untouched. The app requests persistent storage so the browser doesn't evict it.
- **Tree:** `NoteNode.kind` is folder | section | page | board. `CHILD_KINDS` enforces nesting: folders hold anything, sections hold pages and boards. `order` sorts siblings, and `moveNote` rejects invalid moves and moves into a note's own subtree. Drag rows to reorder; dropping on a folder or section moves the item inside.
- **Pages** (`NotePage.tsx`, `markdown.ts`, `NoteRender.tsx`): `marked` (GFM) plus DOMPurify. Raw HTML and `<style>` are allowed; scripts, event handlers and `javascript:` URLs are stripped. The result renders inside a **shadow root**, so a page's CSS only affects that page while theme variables (`--series-1`, `--ink`…) still apply. `[[Title]]` / `[[Title|label]]` link by title (same project first); missing links show red and offer to create the page. Task-list checkboxes in the preview toggle the source. Images can be pasted, dropped or uploaded. Backlinks list pages and board cards that point here.
- **Boards** (`Board.tsx`): React Flow with three node types. *Cards* have a title, markdown body, color, an image as icon or banner (with a pixel-art toggle) and linked notes. *Images* have a caption and pixel-art toggle. *Frames* are tier or group backgrounds, and dragging one carries the nodes whose centers are inside it. Edges use loose connection mode with handles on all four sides, an optional label, and a dashed style. The inspector edits the selection. Double-click the canvas to add a card. Drop an image on a card to attach it, or on the canvas to add an image node; pasting also adds one. "New page for this card" creates a linked page next to the board. `elevateNodesOnSelect` is off so selected frames don't cover their cards. Resize controls are rendered beside each node's content, not inside it, because the content clips overflow. Every edge has an invisible grab strip that stays ~14px on screen at any zoom (`--inv-zoom`), with corner handles and the connection dot at each side's midpoint layered on top.
- **Tree drag-and-drop** uses pointer events (`NotesTree`), not native HTML5 DnD. Moving a row into a section re-mounts its element mid-drop, which can leave Chrome's native drag stuck. Escape cancels a drag.
- **Backups** are version 4: notes plus images as data URLs (since v3), journal and goals (since v4). Older backups still import; sections they don't contain are left alone.

### Journal

- One `JournalEntry` per journal per day (`journal/store.ts#saveEntry` upserts, and removes an entry once its text and mood are both empty). The editor keeps a local draft, saves 600 ms after typing stops, and saves again on blur and when switching days, so nothing is lost on navigation.
- **Encryption** (`journal/crypto.ts`, `vault.ts`, `Privacy.tsx`): optional and covers all journals. PBKDF2-SHA256 (600,000 iterations, random 16-byte salt) derives a non-extractable AES-256-GCM key; every save uses a fresh 12-byte IV. IndexedDB then holds a self-describing envelope (`{format: 'meridian-encrypted', v, kdf, iterations, salt, iv, data}`) in place of the persisted JSON, so a future server can store it without being able to read it. The key lives only in memory for the tab. The store uses `skipHydration`: at startup `detectLock` reads storage, and an encrypted journal stays `locked` (nothing loaded, every write refused) until `unlockJournal` derives the key, reloads the store and only then allows writes. Locking runs `onBeforeLock` callbacks so the editor saves unsaved typing, waits for in-flight encrypted saves, then clears memory. Backups carry `journalEncrypted` (the envelope) in place of `journal`; importing one leaves the journal locked. Changing the passphrase or turning encryption off needs the current passphrase. Forgotten passphrases can't be recovered.
- Mood uses a diverging scale (`moodColor`): red for awful, neutral gray for okay, blue for great. `#tags` are parsed from the text (`tagsIn`). The streak counts consecutive written days ending today, or yesterday while today is still blank.

### Goals

- A `LifeGoal` has no due date and no required order. Momentum (`goals/store.ts#momentum`) compares the average of the last three check-ins with the three before it (±0.75 = rising/slipping).
- **Journal link:** `goal.tag` (lowercase, no `#`) is suggested from the title the first time it's named (`suggestTag`) and can be edited. `goals/parts.tsx#useTaggedEntries` finds entries in any journal whose `tagsIn` contains it; excerpts show the paragraphs that mention the tag. "Write about it" appends the tag to today's Daily entry. Signals are deliberately manual: more time or reps doesn't mean progress.
- **Check-ins** store `answers: {prompt, text}[]` for the goal's `prompts` (default: what did I try / what happened / what did I learn), plus a rating and next step. Answers keep the prompt text, so editing prompts later doesn't garble old check-ins.
- **Weekly review** (`GoalReview.tsx`, route `#/goals/review`): pick goals, then one step per goal. It shows the last check-in and the step you planned, wins, milestones and tagged journal entries since the last review, and signals with a quick log. A check-in form (prefilled if you already reviewed today) sits alongside, with status changes and win logging. `reviewStatus` treats the review as due from the review day (`reviewDay`, default Sunday) until one is completed, and a review up to two days early counts. Goals data is persist version 2; `migrate` fills `tag`, `prompts`, `answers`, `reviews` and `reviewDay` for older data.
- Signals reuse the Health trend chart and line fit: "improving" means the last ~8 values' slope points the way marked better. Practices show linked habits' strength and can be checked off for today; projects show task completion.

### Health

- **Forecasts** (`health/projection.ts`) fit a least-squares line through the last ~6 weeks of daily values. ETA = where the line crosses the target. The range uses slope ± 1.28 standard errors (80%). A slope smaller than half its standard error counts as "holding steady" rather than a trend. `average` goals compare the 7-day average instead.
- **Google Health API** (`health/google.ts`): the legacy Fitbit Web API is retired in September 2026. Sign-in uses Google Identity Services in a popup, and the access token lives in memory only (never persisted or exported). Steps, weight, body fat, and active zone minutes use `dailyRollUp`; resting heart rate and sleep use `list`. Synced readings replace earlier synced readings for the same day but never touch manual entries. The user supplies their own OAuth client ID. Setup steps are on the *Fitbit & Google* tab. **Not yet tested against a live account.**

### Nutrition (Health → Nutrition)

- **Calorie needs** (`health/nutrition.ts#weeklyNeeds`): BMR from Mifflin-St Jeor (10·kg + 6.25·cm − 5·age + 5 for men, −161 for women), multiplied by an everyday-activity factor (1.2–1.7, workouts excluded). Weekly workouts add (MET − 1) × kg × hours on their weekdays (MET 3.5 / 6 / 9 for light / moderate / vigorous). The weight goal adds ±rate × 3,500 kcal/lb ÷ 7 per day. Each weekday gets its own target and the week is their sum. Weight comes from the latest Weight reading, and units follow that measurement (lb → imperial). Warnings cover days under 1,500/1,200 kcal and rates over 1% of body weight per week.
- **Recipes** (`RecipeEditor.tsx`): ingredients store nutrition for their amount. "Paste an ingredient list" parses lines like `1 ½ lb chicken breast` (`parseIngredientLine`). The lookup button searches USDA FoodData Central (`health/usda.ts`) and links the food: values per 100 g plus grams per unit (g/oz/lb, USDA household portions like "cup (202 g)", or a branded serving), so changing the amount rescales. Energy comes from nutrient 1008 or the Atwater 2047/2048 IDs; protein, fat and carbs from 1003/1004/1005. Without a personal api.data.gov key the shared DEMO_KEY allows ~30 lookups/hour. The key is stored in the profile but stripped from backups. Per-serving nutrition can be entered by hand instead.
- **This week** (`planCoverage`, `shoppingList`): meal plans are keyed by week start. Prep target = the sum of daily targets on the days prep covers, minus "other food" per day. Servings needed = covered days × prepped meals per day. Batches step by 0.5. The shopping list merges ingredients by name + unit, scales them by batches, and remembers checked items per week.

### Finance

- **Money is integer cents.** `Transaction.amount` is always positive and `kind` gives the direction. For income, `accountId` is where money arrived. For expenses and transfers it's where money left, and `toAccountId` is where a transfer arrived. A one-sided transfer (the other account isn't tracked) leaves one side empty. `categoryPatch` converts kinds when you pick a category of another kind (e.g. an imported card payment becomes a transfer).
- **Bank formats** (`csv.ts`): `findHeaderRow` skips summary blocks like Bank of America's beginning/ending balances. `detectBank` names recognized exports: Bank of America checking/savings and credit card, Chase card and checking, Capital One 360 and Capital One card. `suggestMapping` handles three amount layouts: one signed column, debit/credit columns, or an unsigned amount plus a Credit/Debit type column. The last mapping used for an account is saved in `importMappings` and reused when the header matches, which also preselects that account. `hintCategory` suggests card payments, transfers (including Capital One's "Deposit from / Withdrawal to"), IRS and Maine Revenue estimated tax payments, interest, refunds, and Chase's own categories. A credit card import that reads mostly as money in shows a "flip the sign" warning. The Chase and Bank of America checking headers were verified against published samples; the Bank of America card and Capital One 360 headers come from common importer conventions, so check the preview on a first import.
- **Import** (`finance/Import.tsx`, `csv.ts`): each row gets an `importKey` (account, date, signed amount, normalized description, occurrence number). Re-imports skip matching keys and flag same-day, same-amount rows as possible duplicates. Rules match description substrings (longest pattern wins), then fall back to a counterparty's default category.
- **Taxes** (`finance/tax.ts`, `taxRules.ts`): this covers a sole proprietor / single-member LLC ("schedule-c" ledgers). Profit = income − deductible expenses (meals 50%). YTD profit is annualized unless the user enters a full-year figure. The calculation includes SE tax (92.35% × 15.3% up to the wage base, plus 0.9% additional Medicare), half-SE and standard/itemized deductions, the QBI deduction (20%, high-income limits not modeled), and brackets. State tax is a flat % of AGI. The required annual payment is the lower of 90% of this year and 100%/110% of last year, minus withholding, split into four installments. Payments in categories with `taxRole` count toward them.
- **State tax** (`finance/stateTax.ts`): Maine uses real brackets (5.8 / 6.75 / 7.15%), Maine's own standard deduction and a $5,300 personal exemption, starting from federal AGI with no QBI deduction. Other states use a flat % of AGI. Maine estimates follow the federal $1,000 threshold and due dates. The safe harbor is the lower of 90% of this year and last year's Maine tax, scaled to 110% when last year's federal AGI was over $150,000 (the conservative reading). High-income phase-outs of Maine's deduction and exemption aren't modeled.
- **Update `taxRules.ts` and `stateTax.ts` every fall** with the new IRS Rev. Proc. brackets and standard deduction, the SSA wage base, and Maine Revenue Services' rate schedules. Unknown years fall back to the latest table with a warning.
- **Overview periods** (`shared.tsx#periodRange`): this month, calendar quarters Q1–Q4 of a chosen year (future quarters disabled), year to date / full year, and the last 12 months. The monthly chart shows the selected year with the chosen quarter highlighted. Balances are grouped into cash (checking/savings/cash), investments, and cards & loans, with net worth and cash after the estimated taxes still due.

### Cloud sync & sharing

- **Server:** Supabase (Postgres, Auth, Storage, Realtime). [`supabase/schema.sql`](supabase/schema.sql) is the single source of truth and is idempotent. Every synced item is one row in `public.records` (`key`, `collection`, `item_id`, `project_id`, `owner_id`, `data` JSON, `deleted`, `modified_at` client ms, `seq` server sequence). Project-scoped collections (`project`, `task`, `note`) are keyed `<collection>:<id>` and readable by project members; everything else is keyed `<owner>:<collection>:<id>` and private. Row-level security plus `push_records()` (batch upsert, newest `modified_at` wins, per-row denials instead of failing the batch) enforce it. Roles live in `project_members` (owner / editor / viewer); invites in `project_invites` (email invites auto-accept on sign-in for confirmed addresses; link tokens expire after 14 days). Membership helpers are `security definer` and deliberately not `STABLE`, because the owner membership is inserted inside the same statement that creates a project. `scripts/test-schema.mjs` runs the schema on PGlite with stand-ins for Supabase's `auth`/`storage` schemas and checks 24 permission scenarios.
- **Engine** (`cloud/engine.ts`, framework-free, tested in `engine.test.ts` against an in-memory server with the same rules): stores are zustand, so a changed item is a new object. Each binding (`cloud/bindings.ts`) describes its collections (list, keyed record or single value; scope; `projectOf`; optional `encode`/`decode`/`shouldHold`). Store diffs become outbox records (latest edit per key, device clock made strictly increasing). Push sends the outbox in batches of 200 with projects first; stale or denied rows are re-fetched so the server's version is restored. Pull reads `seq > cursor − 200` (overlap covers late commits) and skips anything this device has a newer pending edit for. Records a store can't take yet (still loading, journal locked) wait in an inbox. Sync metadata (cursor, versions, outbox, inbox, per-item hash + project) lives in IndexedDB per account. On start, items are compared with their last known hash, so edits made while signed out still upload. The very first run pulls before comparing, so a fresh device's defaults don't overwrite the account. **Safety rule:** an item that belonged to a project and vanished while sync wasn't watching (e.g. a backup import) is restored from the server rather than deleted for every member. View-only edits are reverted locally on the spot.
- **Controller** (`cloud/controller.ts`): starts and stops the engine with the session. On a device whose data belongs to no account or another account, it asks: upload, use the account's data, or cancel. It refreshes memberships (backfilling projects you were added to and dropping ones you lost), accepts email invites, and runs image sync. Realtime changes trigger a pull; without realtime it polls every 15 s in a visible tab and every 60 s in the background. `withSyncPaused` wraps bulk replacements such as imports. Erase and sample data are disabled while signed in.
- **Journal encryption across devices:** the account's setting is a synced `journal-vault` record (`{salt, iterations, check}` or `{off: true}`, never a key). While encryption is on, journal records are sealed one by one with AES-GCM (`{sealed: Envelope}`), and `shouldHold` keeps readable journal data from ever being pushed to an encrypted account. A device that learns the account is encrypted locks its journal until the passphrase is entered, then re-keys its local copy (`switchToAccountKey`). Mismatched passphrases between devices surface as `JournalKeyMismatch`, with an option to take the account's copy.
- **Images:** note images upload to the private `assets` bucket at `projects/<projectId>/<assetId>` once their project exists on the server. Devices without an image download it the first time `assetUrl` needs it (`setRemoteAssetFetcher`), and views retry missing images after notes sync.
- **Assignment:** `Task.assigneeIds` and `Task.createdBy`. `isTaskForMe` filters Today, Calendar and Tasks ("Mine / Everyone's"): in a shared project a task is yours if it's assigned to you, or unassigned and created by you (tasks from before sharing count as the owner's).
- **Editors that keep drafts** (journal, note pages, note titles, boards, goal text) take incoming changes when there's no unsaved typing and keep local typing otherwise; the typing then saves as the newer edit.
- **Installable app:** `public/manifest.webmanifest` (standalone window, taskbar/jump-list shortcuts, `navigate-existing` so the icon focuses the open window), icons drawn by `scripts/make-icons.mjs`, and `public/sw.js` (network-first page, cache-first hashed assets, registered only in production builds; Supabase requests are never cached). `vite.config.ts` uses `base: './'`.
- **Install and update flow:** `src/lib/install.ts` keeps the browser's `beforeinstallprompt` for our own button (and falls back to per-platform instructions), and watches for a waiting service worker. A new version never swaps itself in under a running app: it waits for **Update and restart** (Settings, or the sidebar nudge), or for every window to close.
- **Local stand-in:** `scripts/dev-supabase.mjs` serves just enough of Supabase's Auth, PostgREST and Storage HTTP APIs over PGlite for supabase-js, which makes it possible to test multi-user flows with no account (`DATA_DIR=.dev-supabase` persists data). It has no realtime, and it is for development only.

## Layout

```
src/
  types.ts            data model
  store.ts            persisted Zustand store + all mutations
  ui.ts               dialog + toast state (not persisted)
  lib/                dates, habits (strength/streaks), tasks (locks/layout), plan (clock items), sample data, hooks
  components/         DayClock, charts, editors, shared widgets and inputs
  views/              Today, Tasks, Habits, Calendar, Projects, FlowMap, Areas, Settings
  health/             types, store, projection (forecasts), google (Google Health API), views, sample data
  finance/            types, store, csv, money, tax + taxRules, views (Overview, Transactions, Import, Taxes, Setup…), sample data
  notes/              project notes: tree, markdown pages, flowmap boards, image assets
  journal/            types, store (IndexedDB), crypto + vault (encryption), JournalView, Privacy, sample data
  goals/              types, store (IndexedDB), parts (check-in form, journal links, review banner), GoalsView, GoalReview, sample data
  cloud/              types, engine (+ tests), bindings, config, client, session, auth, remote (Supabase), sharing, assets, controller, ui/ (account, sign-in, share dialog, assignees, sync indicator, join link)
supabase/schema.sql   database tables, row-level security, sync + sharing functions, storage policies
scripts/              test-schema (PGlite security tests), dev-supabase (local stand-in), make-icons
public/               manifest, service worker, icons
  components/TrendChart.tsx   trend/forecast chart, sparkline, grouped column chart
```
